StackSurgeonInternal tool

Paste an Android crash → get a Jira-ready ticket. Optionally, have Claude attempt the fix in your repo on a fresh branch — branch + diff only, you review.

Astro 5 React 18 TypeScript Claude Code CLI Local-only Browser localStorage

The problem

Android crash triage is repetitive, slow, and error-prone:

  • Reading obfuscated stacks — R8/ProGuard names hide intent; framework noise drowns the app frame.
  • Writing tickets — every crash gets the same boilerplate: title, severity, suspected cause, repro steps.
  • Acting on it — even after triage, someone still has to open the repo, find the file, and attempt a fix.

StackSurgeon collapses that loop into paste → Analyze → File-to-Jira and/or Try-Fix, in under a few minutes per crash.

How it works

AI platform

Local claude CLI subprocess (Claude Code), authenticated against whatever account is logged in on the machine — typically a Max plan or Anthropic API key. All LLM work goes through claude --print --output-format=stream-json. No API keys live in the browser. Two modes:

Ticket draft (/api/llm)

Tools disabled. Claude reads the deobfuscated stack, returns one JSON object with title, severity, labels, summary, suspectedCause, reproGuess, confidence. Streamed back as Server-Sent Events; parsed incrementally so fields populate live.

Fix attempt (/api/fix)

Tools enabled — Read, Grep, Glob, Edit, Bash — and cwd set to your connected Android project. Claude creates branch stacksurgeon/fix-<id>, investigates the repo, edits one file, leaves the diff in the working tree, ends with a structured summary.

End-to-end flow

Browser (React island, Zustand store)
  │
  ├─ paste crash (logcat / Crashlytics / Play Vitals) → auto-detect format
  ├─ drag in mapping.txt → parsed in Web Worker (never uploaded)
  ├─ optional code snippet
  │
  ├─► Analyze ▶
  │     parse → deobfuscate → classify frames (app/framework/os/coroutine/native)
  │     /api/llm → spawn claude → SSE stream → incremental JSON parse
  │     ticket draft populates right pane (editable)
  │     auto-saved to history (localStorage)
  │
  ├─► File to Jira → /api/jira proxy (SSRF-guarded) → Atlassian
  │
  └─► Try Fix in connected project
        FixDrawer: pick project + base branch (dropdowns from /api/project-branches)
        Run → /api/fix → projectGuard (ALLOWED_PROJECT_ROOTS, clean tree)
              → git checkout <base> → spawn claude (cwd=project, tools enabled)
              → SSE stream of {text | tool_use | tool_result | final | error}
              → live log in drawer → final diff summary
              → review with: cd <project> && git checkout stacksurgeon/fix-<id>

Privacy posture

DataCrosses to
mapping.txtNowhere — parsed in a Web Worker in the browser tab
Stacktrace + snippetAnthropic Claude API, via local claude CLI subprocess
Jira tokenAtlassian (your Jira), via same-origin Astro proxy
Project source (Fix mode)Anthropic Claude API, via tool invocations from your machine
Request bodiesNever logged on /api/llm or /api/jira

Server-side allowlist (ALLOWED_PROJECT_ROOTS) restricts Fix mode to a configured set of filesystem prefixes. Clean-tree gate refuses fix attempts when the project has tracked-file modifications, so nothing user-typed gets lost.

What the prompt to build it was

"I want to create a tool-based AI, web-based, that can help me with my daily work. I'm an Android engineer. Identify a real problem in my day-to-day workflow that's repetitive, slow, or error-prone, then build a working web tool with a clear intent. The tool must produce an output beyond a text answer (file, ticket, diff, etc.), and be mindful of data privacy."

That single brainstorm prompt drove the whole sequence: pick the problem (crash → ticket factory) from a short list of Android dev pain points → settle on architecture (Astro hybrid + local Claude CLI for LLM, browser-only for mapping.txt, Jira proxy via SSR endpoint) → write design spec → implementation plan → execute. Spec and plan live at docs/superpowers/specs/ and docs/superpowers/plans/.

How to try it

git clone <repo-url> stacksurgeon && cd stacksurgeon
pnpm install
pnpm dev
# open http://localhost:4321/
# click "Try sample crash" → "Analyze ▶"

Optional: open Settings → Connected projects, paste an absolute path to a clean Android repo, then use Try Fix in connected project after any Analyze.
